## 2024-03-24 - Added Focus Visible to Interactive Components
**Learning:** In a highly stylized Next.js app that uses Framer Motion (like `Button.tsx`), it's easy to overlook keyboard accessibility. Utilizing Tailwind's `focus-visible:` utilities (`focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-terracotta/60 focus-visible:ring-offset-2`) is an excellent pattern because it maintains an accessible focus ring *only* for keyboard navigators, keeping the design pristine for mouse users.

**Learning:** In interactive overlays (Modals, Drawers, Banners), icon-only close buttons often miss keyboard-accessible focus states out-of-the-box, even when aria-labels are present. Using 'focus-visible' utility classes in Tailwind allows adding these focus rings for keyboard users without affecting mouse users.
**Action:** When creating or auditing new overlay components or icon-only interactive elements, ensure they explicitly implement both 'aria-label' and 'focus-visible:' utilities tailored to the background color (e.g., 'focus-visible:ring-terracotta/60' for light backgrounds, 'focus-visible:ring-warm-linen/60' for dark backgrounds).
## 2024-10-24 - Input Accessibility and Mobile UX
**Learning:** Placeholders are not a substitute for `aria-label` or `<label>` elements for screen readers. Inputs that lack explicit labels must have an `aria-label` attribute to be accessible. Furthermore, inputs expecting numeric values (like pincodes) should use `inputMode="numeric"` and `pattern="\d*"` to trigger the optimized numeric keypad on mobile devices, greatly improving user experience.
**Action:** Ensure all inputs, especially those relying only on placeholders or icons, have a descriptive `aria-label`. Apply `inputMode="numeric"` and `pattern="\d*"` to any input field that strictly expects numeric data to enhance mobile usability.
